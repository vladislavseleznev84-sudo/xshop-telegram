# GHOST AI

Персональный AI-ассистент для **Telegram Business**: отвечает на входящие сообщения вместо владельца аккаунта —
только в чатах, которые владелец разрешил, и только после явного согласия собеседника.

Стек: Python 3.12 · FastAPI · PostgreSQL + SQLAlchemy (async) · Anthropic Claude API · Telegram Bot API (webhook) · Docker + Caddy.
Без MTProto, юзерботов и перехвата сессий — только официальный Business-механизм Telegram.

## Как это работает

```
Telegram ──webhook──▶ FastAPI ──▶ UpdateRouter ──▶ Engine ──▶ Claude (tool use)
   ▲  (secret header)     │            │             │
   │                      │            │             └─▶ Memory (PostgreSQL, Fernet-шифрование)
   └── sendMessage(business_connection_id) ◀── Outbox ◀──┘
                    Админ: бот-команды + веб-панель (magic-link из Telegram)
```

Каждое входящее проходит «ворота» по порядку, любые из них останавливают обработку:

1. своё сообщение владельца / сообщение бота (`sender_business_bot`) → ответа нет (защита от петель), владелец включает «takeover»-паузу в этом чате;
2. дедупликация (`update_id` и `message_id`) и анти-флуд;
3. команды приватности собеседника (`/ai_off`, `/ai_forget`) — работают всегда;
4. глобальная **пауза**; чат в **белом списке** владельца; у подключения есть право **отвечать**;
5. **согласие** этого чата (`none → pending → granted | declined`, отзыв → `revoked`). До `granted` содержимое не уходит в Claude и не сохраняется;
6. debounce (ждём, пока человек допишет) → лимит ответов в час → Claude → защита от повторов → память → отправка.

Режимы: **shadow** (по умолчанию — черновики приходят только вам) и **live** (отправка собеседнику).
Система стартует **на паузе**: пока вы не выполните `/resume`, ничего не отправляется.

## Команды владельца (в личном чате с ботом)

| Команда | Действие |
|---|---|
| `/start` | справка и текущее состояние |
| `/status` | пауза/режим, ключ Claude, права подключения, состояние webhook |
| `/pause` · `/resume` | мгновенный стоп-кран / запуск автоответов |
| `/stats` | входящие, ответы, черновики, токены |
| `/chats` | чаты с кнопками «Разрешить/Выключить» и «Забыть» |
| `/forget <id>` | удалить память о собеседнике (с подтверждением) |
| `/settings` · `/set <ключ> <значение>` | режим, стиль, тайминги, хранение |
| `/panel` | одноразовая ссылка в веб-панель (для iPhone: «Поделиться → На экран Домой») |

## Что важно знать (ограничения Telegram и проекта)

- Business-чатботы доступны аккаунтам **Telegram Premium**.
- У Bot API **нет метода чтения истории**: бот видит только сообщения, пришедшие *после* подключения. Поэтому «история» накапливается сама — и только после согласия собеседника.
- Inline-кнопки согласия отправляются через `sendMessage` с `business_connection_id`. Если у вас клиент/чат, где `callback_query` не приходит, работает текстовый ответ «да»/«нет». Проверьте кнопки на живом чате при первом запуске.
- Миграций (Alembic) пока нет: схема создаётся `create_all`. Для изменения схемы в будущем — добавить Alembic.
- Один процесс uvicorn (debounce и анти-флуд — в памяти). Для одного бота этого достаточно.
