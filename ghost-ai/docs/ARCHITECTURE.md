# Архитектура

## Слои

| Модуль | Роль |
|---|---|
| `app/main.py` | фабрика FastAPI, webhook `/telegram/webhook`, `/healthz`, заголовки безопасности, жизненный цикл (создание таблиц, `setWebhook`, ретеншн-цикл) |
| `app/telegram/client.py` | клиент Bot API (только документированные методы); ошибки сети не содержат URL с токеном |
| `app/telegram/router.py` | дедупликация апдейтов и маршрутизация: `business_connection`, `business_message`, `deleted_business_messages`, `callback_query`, `message`. `edited_business_message` намеренно игнорируется |
| `app/services/engine.py` | конвейер обработки business-сообщений (см. README), debounce, per-chat lock, takeover, лимиты, защита от повторов |
| `app/services/consent.py` | автомат согласия, inline-кнопки с одноразовыми токенами, привязанными к чату и пользователю |
| `app/services/ai.py`, `prompts.py` | вызов Claude через принудительный tool use (`respond`): ответ, тон, тип отношений, нужен ли владелец, обновления памяти |
| `app/services/memory.py` | профиль собеседника + шифрованная история; слияние без дублей, лимит 40 пунктов на список |
| `app/services/outbox.py` | единая точка отправки: проверка прав подключения, `business_connection_id`, обработка ошибок |
| `app/admin/bot.py` | команды владельца |
| `app/admin/api.py`, `app/web/static` | JSON-API и тёмная PWA-панель (без инлайн-JS/CSS, строгий CSP, пользовательский текст только через `textContent`) |
| `app/state.py` | переключатели в БД (пауза, режим, стиль, лимиты) — общие для бота и панели, переживают рестарт |
| `app/services/retention.py` | ежечасная очистка по политике хранения |

## Решения и компромиссы

- **Пауза по умолчанию + shadow-режим** вместо «включил и надеешься»: первый контакт с живыми людьми происходит под контролем владельца.
- **Пауза перечитывается непосредственно перед отправкой**, поэтому стоп-кран срабатывает, даже если Claude уже думает.
- **Структурный вывод через tool use** вместо парсинга свободного текста: меньше сбоев, а ошибка разбора превращается в «нужен владелец», а не в случайный ответ.
- **Анти-«нейросетевой» стиль** — в системном промпте (без штампов, коротко, язык и регистр собеседника) + настраиваемый владельцем `style_prompt`. Модель не выдумывает факты о владельце и не соглашается на встречи/деньги — эскалирует владельцу.
- **Prompt injection**: текст собеседника передаётся как данные внутри `<conversation>`; отдельный тест проверяет, что он не попадает в системный промпт. Это снижает, но не отменяет риск — поэтому юридически значимые действия модель не совершает, а эскалирует.
- **Один процесс**: debounce/флуд-лимит в памяти. Масштабирование потребует вынести их в Redis.
- **Миграции**: сейчас `create_all`; при первом изменении схемы стоит подключить Alembic.

## Тесты

`python -m pytest -q` — 50 тестов на SQLite in-memory с подставными Telegram и Claude: согласие (ничего не уходит и не пишется до `granted`, отзыв удаляет всё, кнопки одноразовые и привязаны к пользователю), шлюзы движка (пауза, белый список, права, петли, дедуп, лимиты, повторы, takeover, shadow/live), шифрование в БД, ретеншн, webhook-секрет, панель (авторизация, CSRF, magic-link), клиент Claude (forced tool, деградация при мусорном ответе), клиент Telegram (токен не попадает в ошибки).
